# WeCom No-Code Builder

**把一个不懂技术的业务负责人，从零带到能跑——在企业微信里，用自带的智能表格搭出一套「问题从发生到闭环」的系统。全程 0 元、不写代码、不买软件、不找 IT。**

An Agent Skill that walks a non-technical business owner through building a ticket
and project-tracking system entirely inside WeCom (企业微信), using only its built-in
Smart Sheets (智能表格), automation flows, message push, and dashboards.

---

## 它解决什么问题

公司里的售后问题、跨部门协作、项目进度，通常散在微信群、口头转达和 Excel 里。
专业的项目管理软件要么贵、要么员工不愿意学、要么买完了老板自己改不动。

这个 skill 走另一条路：**用公司已经在用的企业微信，搭一条信息管道**——
让问题自己找到该管的人，让进度自己汇到老板眼前。

**它不是「又一个要填的软件」，而是「把已经在产生的信息，自动路由到对的人」。**
这是整套方法能不能活下来的分水岭。

---

## 为什么值得做成一个 skill

这类项目失败几乎从不是因为技术，而是因为**没人用**：老板看两天就不看了，
一线嫌填表麻烦就不填了。

所以这个 skill 的目标不是「搭出一套完美的系统」，而是
**在两周内验证老板真的会看、一线真的会填**。
这两个问题不解决，后面投多少钱都白搭。

## 这个 skill 会带着你做什么

| 步骤 | 内容 | 解决什么 |
|---|---|---|
| **第 0 步** | 先问你「每天最想看的三个数字」 | 决定表要记哪些字段——先建表后想指标，表一定建歪 |
| **第 1 步** | 建一张智能表格 | 有了数据底座 |
| **第 2 步** | 引导你逐列加上 11 个字段 | 工单有主、问题可追溯 |
| **第 3 步** | 配三条自动化规则 | 超期自动催、停机即报、转研发 |
| **第 4 步** | 建群 + 消息推送 | 通知到人 |
| **第 5 步** | 三个数字做成一个屏 | **给你自己看的**——不用挨个问就知道卡在哪 |

第一天只做前两步。配太快，你还没想清楚要什么，表就已经建歪了。

## 设计上的几个关键取舍

**一次只给一步。** 非技术用户看到「接下来还有 5 步」就会放弃。
每一步固定四行：点哪里 / 填什么 / 怎么算做对 / **这一步解决了什么**。
最后一行最重要——他是在拿自己的时间换一个暂时看不见结果的东西。

**不确定就说不确定。** 企微界面随版本变化。agent 如果编一个看起来合理的路径，
用户照着点找不到，就会认为整套方案都是假的然后放弃。
这是这类引导最大的失败风险，所以 skill 里写死了：
**宁可说「我不确定」，也不要编路径。**

**只指路，不动手。** agent 不会去调 API、写脚本、找替代工具。
用户之所以要自己做，是因为**只有他自己能改的东西，才不会被供应商卡住**。

**进度落到文件。** 搭建本来就是跨天的，而对话上下文会丢。
所以有一个 `企微搭建进度.md` 记录进度和自动化规则的 owner。

## 关于界面事实

`references/wecom-facts.md` 里是核实过的企微界面路径、限制和已知的坑，包括：

- 「群机器人」已经改名叫「消息推送」
- 入口是 `文档 → 新建表格 → 智能表格`（不是「工作台」）
- 没有叫「模板中心」的地方
- 免费版自动化流程每人每月 100 次
- 智能表格不能打印、导不出 PDF
- 「创建待办」在已知的自动化动作清单里都没有——**配之前要看一眼实际列表**

**这些会随版本变化。** 如果发现和你的界面不符，以你看到的为准。

## 适用 / 不适用

**适合**：中小企业、硬件/制造业团队，已经在用企业微信，想低成本把售后、
问题追踪、跨部门协作管起来，且希望自己能随时改。

**不适合**：需要复杂审批流、需要和 ERP 深度集成、需要严格权限模型。
那些要上自建应用或专业系统——这个 skill 的定位是**先跑通、先验证有人用**。
