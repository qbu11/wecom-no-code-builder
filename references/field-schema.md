# 工单表字段清单

**一次只引导用户加一列**，加完确认再加下一列。
不要一次把整张清单贴给他——非技术用户看到 11 列会直接放弃。

标 ⚠️ 的列，加的时候要专门说明它为什么重要，不要默默加过去。

| # | 字段 | 类型 | 说明 |
|---|---|---|---|
| 1 | 工单号 | 自动编号 | 系统自己生成 |
| 2 | 来源 | 单选 | 客户报修 / 现场巡检 / 代理商 / 内部发现 |
| 3 | **设备编号** | 文本 | ⚠️ 见下 |
| 4 | 客户 / 国家 | 文本 | 海外业务要能按国家筛 |
| 5 | 问题描述 | 多行文本 | |
| 6 | 现场照片 | 附件 | |
| 7 | 责任部门 | 单选 | 售后 / 研发 / 工艺 / 生产 |
| 8 | **责任人** | 成员 | ⚠️ 见下 |
| 9 | 紧急度 | 单选 | 停机型 / 影响生产 / 一般 |
| 10 | 状态 | 单选 | 待分派 / 处理中 / 待研发 / 已解决 / 已关闭 |
| 11 | 承诺完成时间 | 日期 | ⚠️ 见下 |

## 三列必须专门说明的字段

### 3. 设备编号 —— 这是以后查故障历史的钥匙

跟用户这样解释：**没有这一列，这堆工单过半年就是一堆死数据**；
有了它，才能回答「这台机器历史上出过几次问题」「哪个型号老出毛病」，
而后者直接指向设计问题。

所以要让一线填。但如果让一线专门去查编号，他就不填了——
编号应该从他们已经在做的事里带出来（比如报修时随手拍铭牌）。

### 8. 责任人 —— 这一列不能空

空着就等于这个问题没人管。
配合第 3 步的自动化规则，「超期」才有对象可以通知。

### 11. 承诺完成时间 —— 超期预警靠它算

没有这个日期，系统就不知道什么叫「超期」，
所有催办和升级都无从谈起。

## 如果用户嫌麻烦

给最小版本：**只加「责任人」和「状态」两列**，先跑起来。
告诉他：「剩下的列以后随时能加，先跑起来更要紧。」

## 字段设计的两条隐含原则

**一、能用单选的，不要用文本。**
单选才能做看板分组、做仪表盘统计。文本列在报表里基本没用。

**二、不要让一线新增动作。**
每加一列都问自己：这一列需要一线专门去填吗？
如果需要，就要怀疑——**这套系统如果要求一线「填表」，它就会死**。
正确做法是从他们已经在做的事里自动抓（发群消息、拍照）。
