# 进度文件

**开工前先建一个 `企微搭建进度.md`，每完成一步就更新它。**

---

## 为什么要这个文件

1. **会话会中断。** 这个搭建流程本来就是「今天做两步、明天继续」，
   而 agent 的对话上下文一关就没了。有了文件，用户明天只要说
   「读一下进度文件，继续」，你就能接上，他不用重新说一遍。
2. **自动化规则需要 owner 登记**（谁设的 / 谁批准的 / 哪天生效）。
   这是治理，也是他以后改坏了能回滚的唯一依据。
3. **用户会忘。** 两个星期后他会忘了当初为什么这么设计、那三个数字是怎么定的。

---

## 文件内容模板

```markdown
# 企微系统搭建进度

## 基本信息
- 公司/团队：
- 现在这类问题怎么流转：
- 搭建开始日期：

## 三个数字（用户最想每天看到的）
1.
2.
3.

## 进度
- [ ] 第 1 步 · 建表（表名：          位置：          ）
- [ ] 第 2 步 · 加字段（已加到第 ___ 列）
- [ ] 第 3 步 · 配自动化流程
- [ ] 第 4 步 · 建群 + 消息推送（群名：          ）
- [ ] 第 5 步 · 仪表盘 + 视图

## 自动化规则登记
| 规则 | 触发条件 | 动作 | 谁设的 | 谁批准的 | 生效日期 |
|---|---|---|---|---|---|
| | | | | | |

## 踩过的坑 / 待办
-
```

---

## 使用方式

- **开工前**：先建这个文件，告诉用户「我建了个文件帮你记进度，明天接着做不用重说」
- **每完成一步**：更新「进度」
- **配完自动化规则**：填「自动化规则登记」表——这步不要省
- **建完文件**：**告诉用户文件建在哪个目录了**，否则他明天找不到
- **续做时**：让用户说「读一下进度文件」，或者主动先读

---

## 注意

- 文件建在**用户自己选的工作目录**，不要建在别处
- 如果用户不知道建在哪，问他平时放文件的地方，或者建议桌面/文档目录
- 不要在文件里记录任何账号、密码、密钥
